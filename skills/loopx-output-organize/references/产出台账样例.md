# 产出台账样例 v2

以下三份均为版本台账，字段按工作区 `docs/v2实现契约.md` §6、§13。JSON 可作结构示例，不能直接当真实产出提交：摘要、字节数、时间和指标是演示值，需由工具扫描实际文件生成；引用须指向真实版本。
`中文目录名` 从产出根算起，产物与执行记录路径从本版本目录算起。三份共用的字段说明在文末逐项列出。

## 字段说明（适用于以上三份）

| 字段 | 中文说明 |
|---|---|
| `schema_version` | 台账结构版本，v2 固定为字符串 `2.0`，与 skill 发布版本 `2.0.0` 分开 |
| `引用` | 本课题的节点版本引用，如 `2.2@v2`；嵌套调用带父引用前缀 |
| `节点` | 流程中的节点 ID；嵌套时为被调用名 |
| `版本` | 本节点正整数版本号，与引用和第N版目录一致 |
| `课题` | 课题 ID，如 `q3-bcard` |
| `中文目录名` | 从产出根起算的实际版本目录，不含产出根本身 |
| `执行方` | skill / 代码 / 人工 / 配置 / 智能体 / 报告整合；外部团队不是执行方枚举 |
| `外部团队` | 外部交付方名称，无则 null；非空时触发必须为外部接收 |
| `skill` | 关联 skill 的来源信息，无关联时为 null，人工样例不虚构 skill |
| `skill.名称` | 业务 skill 标识 |
| `skill.中文名` | 业务 skill 中文展示名 |
| `skill.skill版本` | 业务 skill 自身代码版本，与产出版本独立 |
| `skill.来源sha256` | 业务 SKILL.md 源文件的真实摘要 |
| `创建时间` | 分配时的 ISO 8601 时间，保留时区 |
| `完成时间` | 提交时间；进行中占位为 null |
| `执行状态` | 本版运行状态；成功、部分完成为完成态，不等同于评审通过 |
| `触发.类型` | 首次 / 打回 / 补证 / 循环 / 外部接收 / 重跑 |
| `触发.编号` | 打回或补证事件的编号，其他触发为 null；循环不是用此字段记轮次 |
| `输入[].引用` | 依赖、基线或参考的版本引用，也可为交接或跳过引用 |
| `输入[].角色` | 依赖 / 基线 / 参考；仅依赖参与有效性推算 |
| `基线` | 比较基线对象，无基线时 null |
| `基线.引用` | 被比较的本课题或跨课题版本，也同时写入基线角色的输入 |
| `基线.策略` | 上一版 / 固定首版 / 无，按实际分配选择记录 |
| `评审结论` | 门禁评审对象，非门禁为 null |
| `评审结论.结论` | 四种通用结论之一 |
| `评审结论.原文` | 流程专用结论文案，或 null |
| `评审结论.理由` | 评审判断的原因 |
| `评审结论.目标` | 打回或补证的目标节点 ID 列表 |
| `未解决项` | 本版带问题通过登记的问题，三例均无所以为 [] |
| `未解决项[].描述` | 问题说明，必填 |
| `未解决项[].指标` | 实际指标描述，可为空字符串 |
| `未解决项[].标准` | 对照的标准，可为空字符串 |
| `未解决项[].差值` | 与标准的差异，可为空字符串 |
| `artifacts` | 当前版本的实际文件清单，不含台账本身与内部调用产物 |
| `artifacts[].相对路径` | 以版本目录为基准的文件路径 |
| `artifacts[].类型` | 文件所在四区：报告 / 数据 / 执行记录 / 日志 |
| `artifacts[].角色` | 主交付物或附属；完成态恰好一个主交付物 |
| `artifacts[].sha256` | 文件实际内容的 SHA-256 |
| `artifacts[].字节数` | 文件实际字节数 |
| `metrics` | 指标对象，代码样例的 KS 为演示业务指标，无指标时 {} |
| `children` | 嵌套调用引用列表，如 `2.2@v2/取数@v1`；无调用时 [] |
| `会话` | 来源会话标识，仅留痕，不创建会话目录 |
| `执行记录` | skill、代码、智能体完成态必填；人工样例可省略 |
| `执行记录.路径` | trace JSONL 的相对路径 |
| `执行记录.步骤数` | 执行记录统计的步骤数 |
| `执行记录.失败数` | 执行记录统计的失败步骤数 |
| `轮次记录` | 可选对象；有每轮必记要求的节点提交完成态时必须完整提供 |
| `轮次记录.本轮调整` | 本轮具体调整内容，非空字符串 |
| `轮次记录.复评结果` | 本轮重新评估结果，非空字符串 |
| `轮次记录.接受或拒绝原因` | 采用或拒绝本轮结果的理由，非空字符串 |

## 常见错误

- 沿用 v1 的 `kind / 标准ID / 执行ID / 版本号 / inputs`；v2 使用上述字段，不建执行级台账。
- 把门禁「整改后复验」写成执行失败；确认记录成功与业务结果不合格可以同时成立。
- 把打回来源写成依赖，使模型与门禁相互依赖；应由 alloc 添加为参考。
- 忘记基线同时写入输入，或用上一轮替代固定首版；跨课题基线须带课题 ID。
- 漏唯一主交付物、漏要求的执行记录；失败和进行中允许缺少，不能因此伪造文件。
- 把打回编号、循环版本号和 skill 代码版本混用，或让失败版本不占号。
- 使用示例摘要冒充真实摘要，或手改已提交台账掩盖文件变化；应扫描实际文件并保留历史。
- 在台账里增写有效性或当前采用；这些状态由事件和依赖推算，择优应使用 adopt。
- 循环完成态漏 `轮次记录`，或使用与流程不一致的键；提交时用 `--round` 完整提供。
