# 产出台账样例

以下三段都是合法 JSON，可分别复制为对应目录中的 `产出台账.json`。示例中的 SHA-256 和字节数仅用于展示格式，实际落盘时须从对应文件计算。`中文目录名` 从 `产出/` 起算；`artifacts[].相对路径` 和 `执行记录.路径` 从这份台账所在目录起算。`标准ID` 与目录名分别供机器和人识别，不要求逐字相同；两者须指向同一个课题、执行或版本。

## 版本级：风险报告第 2 版

位置：`产出/【课题】Q3风险复盘/第1次执行_0923下午/各环节产出/风险报告/第2版/产出台账.json`

```json
{
  "schema_version": "1.0",
  "kind": "版本",
  "标准ID": "q3-risk-review/report-skill/v2",
  "中文目录名": "【课题】Q3风险复盘/第1次执行_0923下午/各环节产出/风险报告/第2版",
  "课题ID": "q3-risk-review",
  "执行ID": "q3-risk-review/run-1",
  "版本号": 2,
  "上一版版本号": 1,
  "skill": {
    "名称": "report-skill",
    "中文名": "风险报告",
    "skill版本": "1.3.0",
    "来源sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
  },
  "创建时间": "2026-09-23T14:30:00+08:00",
  "状态": "成功",
  "inputs": [
    { "类型": "产物", "引用": "q3-risk-review/data-skill/v1", "角色": "上游" },
    { "类型": "产物", "引用": "q3-risk-review/report-skill/v1", "角色": "基线" },
    { "类型": "用户", "引用": "【课题】Q3风险复盘/第1次执行_0923下午/我的需求/需求.md", "角色": "参考" }
  ],
  "artifacts": [
    { "相对路径": "报告/Q3风险报告.md", "类型": "报告", "角色": "主交付物", "sha256": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb", "字节数": 2048 },
    { "相对路径": "执行记录/trace.jsonl", "类型": "执行记录", "角色": "附属", "sha256": "cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc", "字节数": 512 }
  ],
  "执行记录": { "路径": "执行记录/trace.jsonl", "步骤数": 6, "失败数": 0 },
  "metrics": { "规范得分": 0.86, "执行耗时毫秒": 38000 },
  "children": []
}
```

| 字段 | 中文注释 |
|---|---|
| `schema_version` / `kind` | 台账契约版本；这一份记录的是单个 skill 的一个产出版本。 |
| `标准ID` / `中文目录名` | 稳定的机器标识；实际落盘的中文目录路径。`v2` 对应 `第2版`。 |
| `课题ID` / `执行ID` | 所属课题和本次对话执行的标准 ID。 |
| `版本号` / `上一版版本号` | 当前版本及同一 skill 版本线的前一版；第 1 版填 `null`。跨执行继续调优也沿用同一版本线。 |
| `skill.名称` / `skill.中文名` | skill 的英文 slug 与目录展示名。 |
| `skill.skill版本` / `skill.来源sha256` | 运行时 skill 自身的版本与来源内容摘要，不是产出版本号或报告摘要。 |
| `创建时间` / `状态` | ISO 8601 时间；本版运行结果，也可以是 `部分完成` 或 `失败`。 |
| `inputs[].类型` / `引用` / `角色` | 输入来源、可追溯位置或标准 ID、用途。`基线` 指向同一 skill 的上一版产物，便于比较。 |
| `artifacts[].相对路径` / `类型` / `角色` | 产物文件路径、分类、交付定位；全表恰好一个 `主交付物`。 |
| `artifacts[].sha256` / `字节数` | 对该文件实际字节计算的摘要和大小。 |
| `执行记录.路径` / `步骤数` / `失败数` | trace JSONL 文件及其中步骤总数、失败步骤数；文件内容沿用已有 trace 契约。 |
| `metrics` | 自由指标对象，指标名称和口径由产出方确定。 |
| `children` | 此 skill 内部调用的子 skill 产出版本标准 ID；没有内部调用时为空数组。 |

```json
  "执行ID": "q3-risk-review/run-1",

    { "类型": "用户", "引用": "我的需求/需求.md", "角色": "参考" }

  "artifacts": [
    { "相对路径": "最终交付/Q3风险复盘.html", "类型": "报告", "角色": "主交付物", "sha256": "dddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddd", "字节数": 4096 },
    { "相对路径": "执行记录/trace.jsonl", "类型": "执行记录", "角色": "附属", "sha256": "eeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeee", "字节数": 768 }
  ],
  "执行记录": { "路径": "执行记录/trace.jsonl", "步骤数": 12, "失败数": 0 },

```

| 字段 | 中文注释 |
|---|---|
| `schema_version` / `kind` | 同一台账契约；这一份记录一次对话执行。 |
| `标准ID` / `中文目录名` | 执行的机器标识与实际中文目录路径。 |
| `课题ID` / `执行ID` | 所属课题；当前执行的 ID，应与 `标准ID` 相同。 |
| `创建时间` / `状态` | 执行创建时间与最终状态。 |
| `inputs[].类型` / `引用` / `角色` | 本次执行的输入来源、位置和用途。 |
| `artifacts[].相对路径` / `类型` / `角色` / `sha256` / `字节数` | 最终交付文件及附属文件的路径、分类、角色、摘要和大小。 |
| `执行记录.路径` / `步骤数` / `失败数` | 编排层 trace JSONL 文件及步骤计数。 |
| `metrics` / `children` | 本次执行的汇总指标；仅内部嵌套调用才列入 `children`。 |
| `steps[].顺序` / `skill名称` / `最终采用版本ID` | skill 编排顺序、英文名称及各 skill 最终选用的产出版本。重跑过的旧版不写成最终采用版。 |

## 课题级：Q3 风险复盘

位置：`产出/【课题】Q3风险复盘/产出台账.json`

```json
{
  "schema_version": "1.0",
  "kind": "课题",
  "标准ID": "q3-risk-review",
  "中文目录名": "【课题】Q3风险复盘",
  "课题ID": "q3-risk-review",
  "创建时间": "2026-09-23T13:50:00+08:00",
  "状态": "成功",
  "inputs": [
    { "类型": "用户", "引用": "课题说明.md", "角色": "参考" }
  ],
  "artifacts": [
    { "相对路径": "课题说明.md", "类型": "报告", "角色": "主交付物", "sha256": "ffffffffffffffffffffffffffffffffffffffffffffffffffffffffffffffff", "字节数": 1024 }
  ],
  "metrics": {},
  "children": [],
  "目标": "完成 Q3 风险复盘并保留各次执行与报告版本的对比依据。",
  "验收标准": ["最终交付可阅读", "报告调优版本可追溯并能与基线比较"],
  "累计执行列表": ["q3-risk-review/run-1"]
}
```

| 字段 | 中文注释 |
|---|---|
| `schema_version` / `kind` | 同一台账契约；这一份记录跨对话课题。 |
| `标准ID` / `中文目录名` | 课题的机器标识与实际中文目录路径。 |
| `课题ID` | 当前课题 ID，应与 `标准ID` 相同。 |
| `创建时间` / `状态` | 课题创建时间与当前进展状态。 |
| `inputs[].类型` / `引用` / `角色` | 课题需求的来源、位置和用途。 |
| `artifacts[].相对路径` / `类型` / `角色` / `sha256` / `字节数` | 课题说明文件的路径、分类、角色、摘要和大小。 |
| `metrics` / `children` | 课题汇总指标；内部嵌套调用的版本 ID，没有则为空数组。 |
| `目标` / `验收标准` | 跨执行的业务目标与逐项可核对的完成条件。 |
| `累计执行列表` | 本课题历次对话执行的标准 ID，按执行顺序累计追加。 |

## 常见错误

- **漏主交付物**：`artifacts` 必须恰好有一个 `角色: "主交付物"`；执行失败也应保留可检查的实际产物后再落台账。
- **基线指错**：报告第 2 版的 `基线` 应引用同一 skill 的报告第 1 版标准 ID，不能指向上游取数或另一课题。`上一版版本号` 与它对应。
- **版本号跳号**：同一课题、同一 skill 跨执行连续编号；第 1、2、3 版依次递增，不能从第 1 版直接跳到第 3 版。
- **中文目录名与标准ID不一致**：两者写法可以不同，但必须指向同一实体。例如 `report-skill/v2` 对应 `风险报告/第2版`，不能对应 `风险报告/第3版`。
