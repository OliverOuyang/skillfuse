# 产出规范

面向业务 skill 和产出管家的落盘契约。目录名供人阅读，机器关联以 `产出台账.json` 中的标准 ID 和版本号为准。确定性的建目录、编号、记账与索引更新由产出管家脚本完成；业务 skill 声明主交付物和附带数据。

## 一、三层边界与生命周期

| 层 | 边界与生命周期 | 命名及校验 |
|---|---|---|
| 课题（task） | 一个业务需求；可跨日期、对话和多次执行。建立时记录目标、验收标准，后续更新累计进展；历史执行保留。 | `【课题】<课题名>/`，其下有 `课题说明.md`。同一需求继续使用原课题，不因新对话另开课题。 |
| 执行（run） | 一次对话对应一次执行；本次输入、编排与交付独立存放。新对话接续同一课题时新增执行，不改写既有执行。 | `第N次执行_MMDD上午|下午|晚上/`，`N` 在本课题内从 1 递增；其下有 `本次说明.md`、`我的需求/`、`最终交付/`、`各环节产出/`。 |
| 版本（version） | 某业务 skill 的一次生成或重跑；无论最终是成功、部分完成还是失败，都占一个版本并保留。 | `各环节产出/<skill中文名>/第N版/`；`N` 取该课题与该 skill 的 `output_version`。 |

同日同一时段执行两次，先以不同的「第N次执行」序号区分，如 `第1次执行_0923上午/`、`第2次执行_0923上午/`；若既有目录仍重名，在时段后追加可读序号（如 `_2`），不得覆盖。精确开始时间记录在台账中，不拼进目录名。

## 二、目录与内容

```text
产出/
└── 【课题】<课题名>/
    ├── 课题说明.md
    ├── 第1次执行_0923上午/
    │   ├── 本次说明.md
    │   ├── 我的需求/
    │   ├── 最终交付/
    │   ├── 执行记录/                         # 多 skill 编排时的执行层记录
    │   └── 各环节产出/
    │       └── <skill中文名>/
    │           └── 第1版/
    │               ├── 产出台账.json
    │               ├── 报告/
    │               ├── 数据/
    │               ├── 执行记录/
    │               ├── 日志/
    │               └── 内部调用/             # 仅发生嵌套调用时
    │                   └── <子skill中文名>/第1版/
    └── 版本对比/
        └── <skill中文名>/
            ├── 第1版
            └── 最新版
```

| 路径 | 放置规则 |
|---|---|
| `课题说明.md` | 课题目标、验收标准、累计进展及已尝试方案。 |
| `本次说明.md` | 本次做的事、skill 编排顺序、各 skill 最终采用的版本和结论。 |
| `我的需求/` | 本次需求原文和上传附件；不同执行不混放。 |
| `最终交付/` | 本次对外给出的成品；多 skill 汇总件也放这里。 |
| `各环节产出/<skill中文名>/第N版/` | 每个 skill 的每次生成单独成版；不同 skill 的版本数可以不同。 |
| `报告/`、`数据/` | 分别放人看的交付物和机器读的数据。 |
| `执行记录/`、`日志/` | 分别放结构化步骤记录和原始运行日志。编排层记录放执行目录的 `执行记录/`，skill 步骤记录放对应版本的 `执行记录/`。 |
| `内部调用/` | 某版本内部调用另一 skill 时，按 `<子skill中文名>/第N版/` 递归存放，并保留从属关系。子 skill 的产物只记进它自己的台账，父台账通过 `children` 记录子版本标准 ID，不重复记账。 |

每个版本目录固定包含 `产出台账.json` 与 `报告/`、`数据/`、`执行记录/`、`日志/` 四区，即使某区本次没有文件也保留目录；`内部调用/` 按需增加。`产出台账.json` 至少记标准 ID、所属课题与执行、skill、`output_version`、精确时间、状态、输入、产出、上一版与可用的对比指标，供追溯和校验。版本之间不得覆写文件。

## 三、编号、状态与版本线

| 规则 | 可校验结果 |
|---|---|
| `output_version` 的作用域是（课题，skill）。 | 同一课题中该 skill 从 1 单调递增，跨执行连续；不同课题各自从 1 开始，不能共享编号。 |
| 重跑分配新版本。 | 旧版目录、台账及失败现场原样保留；新版台账指向上一版。 |
| 状态为 `进行中`、`成功`、`部分完成`、`失败` 四态。 | 目录刚分配、尚未收尾时记 `进行中`；缺图表等未完成项记 `部分完成`；失败版仍保留台账、已生成内容、执行记录和日志，并占用版本号。 |
| 只有完成态（`成功`、`部分完成`）强制完整产物。 | 完成态必须恰好一个主交付物，版本级还必须有执行记录；`进行中` 与 `失败` 允许缺失——保住现场优先于满足格式。 |
| 本次采用的版本由 `本次说明.md` 指明。 | 不能仅凭最大版本号推断最终交付采用了哪版。 |

`内部调用/` 中的子 skill 也按所属课题与自身 skill 计数，不随父 skill 的版本号重置。

`版本对比/<skill中文名>/第N版` 和 `最新版` 使用**索引文件**，不使用软链：索引写明目标版本目录的相对路径及状态；`最新版` 指向编号最大的已记录版本。每新增一版就新增该版索引并更新 `最新版`，不可删改旧版索引所指的历史产出。索引文件便于 macOS 与 Windows 直接读取，避免软链创建权限和跨平台复制问题。比较时读取各版台账中的上一版、指标和产出路径；失败版同样进入版本线。

## 四、临时区与产出根

未确定课题时，在 `产出/【临时】<描述>/` 下按同样的执行、版本结构落盘；事后可整体归并到正式 `【课题】<课题名>/`，并同步修正台账中的课题关联及版本对比索引，保持版本可追溯。临时区不要求使用者预先命名正式课题。

产出根解析优先级：显式参数 > 环境变量 `SKILLFUSE_OUTPUT_ROOT` > 项目根目录下的 `产出/`。最终产出根必须位于项目根目录下；显式参数或环境变量解析到项目根之外时应报错，不可落到全局目录。解析后在该根下创建 `【课题】…/` 或 `【临时】…/`。

## 五、沿用 trace 契约

`执行记录/` 存逐步执行的结构化 JSONL；原始 stdout/stderr 等运行日志存 `日志/`。每行记录直接遵守 `src/core/traceContract.ts` 的 `TRACE_STEP_SCHEMA`，不另定义 span 或字段：

| 字段 | 规则 |
|---|---|
| `ts`、`step`、`status`、`duration_ms` | 必填；`ts` 为 date-time，`duration_ms` 为非负数，`status` 仅 `ok`、`fail`、`skip`。 |
| `step` | 仅 `skill.activate`、`skill.load`、`skill.run_script`、`tool.execute`、`guardrail.check`、`human.review`。 |
| `attrs` | 可选对象，承载已有 `gen_ai.skill.*` 属性。 |
| `error` | 发生错误时记录 `type`、`message`；不得增加契约外字段。 |

台账的 `进行中`、`成功`、`部分完成`、`失败` 是**版本状态**；trace 的 `ok`、`fail`、`skip` 是**步骤状态**，两者分别记录，不混用。

执行层的 `执行记录/` 是可选的：多 skill 编排时用它记录谁先谁后，但编排顺序本身已由执行台账的 `steps[]` 承载，所以不强制。版本层的执行记录在完成态必填。
