# 产出规范 v2

本规范面向业务 skill 与编排方。唯一事实来源为工作区 `docs/v2实现契约.md`，§13 的补充优先于前文；命令示例见 `../SKILL.md`，台账示例见 `产出台账样例.md`。

## 三种状态

三种状态是三个维度，不是三个枚举值。执行成功不代表评审通过，评审通过不保证依赖仍有效。

| 维度 | 取值 | 决定方式 |
|---|---|---|
| `执行状态` | 进行中 / 成功 / 部分完成 / 失败 | alloc 创建进行中台账，commit 提交实际结果 |
| `评审结论.结论` | 通过 / 带问题通过 / 整改后复验 / 补证后再判 | 门禁完成态必填，非门禁不能给结论 |
| 有效性 | 当前采用 / 已替代 / 过期 / 进行中 / 失败 | 从目录、台账和事件推算，不写回台账 |

视图把「当前采用」的有效性显示为「有效」。带问题通过至少登记一个未解决项；整改与补证指定目标，超出允许范围等情形按契约要求人工确认。

## 五条版本规则

1. **按课题内节点编号**：从第1版递增，失败也占号；重跑新分配，历史不覆盖、不删改。嵌套调用只在同一父版本的被调用名下计数。
2. **编号各管一件事**：节点版本、打回、补证、交接、未解决项编号分别计数；skill 代码版本另记在 `skill.skill版本`。
3. **当前采用不等于最新编号**：完成态提交、adopt、skip 按事件顺序生效。adopt 可选历史完成态，后续失败版不替换当前采用。
4. **有效性按依赖推算**：只检查 `输入.角色` 为「依赖」的引用；上游换版、取消跳过或依赖传递过期会让下游过期。「基线」「参考」不参与推算。进行中、失败先按执行状态显示，非当前版本显示已替代。
5. **阶段依赖用冻结交接表达**：依赖写 `交接:<名>`，alloc 记录最新同名 `交接#N`；阶段内部换版不改变已交接快照，新同名交接才让使用旧交接的下游过期。工具按流程声明处理依赖。

## 目录与命名

```text
<产出根>/
├── .当前状态.json
├── 总索引.md
└── <智能体>/【课题】<名>/                 # 临时为【临时】<名>
    ├── 课题.json
    ├── 课题说明.md
    ├── 流程定义.json
    ├── 流转记录.jsonl
    ├── 总览.md
    ├── 未解决项.md
    ├── <分组…>/<节点>/
    │   ├── 当前采用_第N版.md
    │   └── 第N版/
    │       ├── 产出台账.json
    │       ├── 报告/
    │       ├── 数据/
    │       ├── 执行记录/
    │       ├── 日志/
    │       └── 内部调用/<名>/第N版/       # 按需
    └── 交接与交付/交接<N>_<交接名>_<MMDD>/
        ├── 清单.json
        ├── 交接说明.md
        └── 交付物/<节点目录名>/<主交付物文件名>
```

- 智能体目录取流程名，无流程时为「单独调用」。流程源可为 YAML 或 JSON，开课题时规范化并冻结为 `流程定义.json`；更新走 flow-update。
- 分组和节点目录为 `<id>_<名称>`，无名称只用 `<id>`；首次进入流程时确定 `目录`，后续改名不改路径。
- 节点 ID 不得为空，不得含 `/ @ # :`、空白或控制字符。名称经 sanitize_name 去除路径分隔符和控制字符，禁止空名与纯点段。
- `课题ID` 可用 `--slug` 指定小写英文 slug；缺省为 `task-<名称 UTF-8 十六进制>`。
- 不建对话目录或「版本对比」目录。会话 ID 只记在台账、事件中；总览版本线和节点版本历史保留失败与候选版本。
- 节点索引每次刷新至多一个：无版本不写；有版本但未采用为 `当前采用_无.md`；有效采用为 `当前采用_第N版.md`；过期加 `_已过期`；跳过为 `已跳过.md`；待重做在 `.md` 前加 `_待重做`。
- 节点索引标题为 `# <id> <名称>`，无名称只写 id；历史表时间显示本地 `MM-DD HH:MM`，台账仍保留原始时间。

业务 skill 只写 alloc 返回的 `SKILLFUSE_OUTPUT_DIR`。四区始终创建，主交付物从实际文件中唯一指定。完成态（成功、部分完成）必须恰好一个主交付物，执行方为 skill、代码、智能体时还必须有执行记录；进行中、失败至多一个主交付物，其余不强制。
台账从产出根记录 `中文目录名`，产物路径相对版本目录；文件摘要与字节数按真实内容计算。内部调用独立记账，父台账通过 `children` 关联，不重复扫描子产物。
`轮次记录` 的键按 `循环.每轮必记`，值为非空字符串；完成态缺项拒绝提交。基线与上一版目录分别提供，不把固定首版误当上一轮。

## 事件类型

`流转记录.jsonl` 只追加，每行一个 JSON，公共字段为 `序号 / 时间 / 会话 / 类型`。事件序号连续；打回、补证、交接、未解决项编号在本课题各自从 1 递增。

| 类型 | 记录内容 |
|---|---|
| 开课题 | 流程、流程版本、继承 |
| 分配 | 节点、版本、触发、基线 |
| 提交 | 节点、版本、执行状态、评审结论 |
| 打回 | 编号、来源、目标、原因、跨阶段、人工确认 |
| 补证 | 编号、来源、目标、原因、人工确认 |
| 采用 | 节点、版本、原因 |
| 跳过 | 节点、原因、人工确认 |
| 交接 | 编号、名称、节点、清单、未解决项、人工确认 |
| 未解决项 | 编号、动作；新增记来源与问题，关闭记处理与原因 |
| 流程变更 | 摘要、原因 |

「外部接收」「循环」「重跑」是版本的 `触发.类型`，不是额外事件类型。全部触发取值为「首次 / 打回 / 补证 / 循环 / 外部接收 / 重跑」，编号仅打回、补证时非空。
打回与补证直到目标节点有相应触发的完成态版本才算消费；失败重试继续关联原事件。alloc 将该事件来源加入「参考」输入，并返回 `重做要求`。

## 交接与最终交付

交接范围是同阶段未移出的全部节点。未采用、过期、未通过的门禁阻止交接；跳过视为允许。人工确认可携问题交接，确认原因与问题留痕；没有定义交接名的节点不能交接。
只复制各节点主交付物到 `交付物/`，数据不复制，通过清单中的版本引用追溯。`清单.json` 冻结引用、主交付物、sha256、未解决项和人工确认。
最终交接是流程顺序中最靠后的交接节点。全部未解决项先用 issue-close 处置为「接受 / 已解决 / 后续处理」；未关闭时默认拒绝，确需例外用 `--confirm` 明示原因。
交接完成后上游更新，总览提示原交接已落后；需重新交接才能形成新快照。

## 跨课题引用

| 引用 | 含义 |
|---|---|
| `2.2@v3` | 本课题节点版本 |
| `1.3@跳过` | 被跳过节点，仅用于输入 |
| `交接#2` | 本课题交接 |
| `q3-bcard/2.2@v3` | 另一课题节点版本 |
| `q3-bcard/交接#4` | 另一课题交接，可用于继承 |
| `2.2@v3/取数@v1` | 父版本下嵌套调用 |

跨课题按 `课题ID` 在同一产出根的全部智能体目录查找。task-begin 的 `--inherit` 写课题元数据与课题说明；alloc 的 `--baseline` 显式指定跨课题版本，写入基线对象与「基线」输入，并返回真实基线目录；它不参与有效性推算。
diff 用 `--from-task` 选择另一课题的同节点版本。verify 核验跨课题引用，课题或版本不存在报 error；继承声明不能代替实际可访问的历史文件。

产出根：显式 `--output-root` > `SKILLFUSE_OUTPUT_ROOT` > 项目根/产出，必须位于项目根内。verify 输出问题位置与修复建议，有 error 时退出码为 1；不要手改摘要来掩盖历史文件变化。
